## 关系演算回顾：存在量词与全称量词

上一讲引入了元组关系演算（Alpha 语言）中的**存在量词（∃）**，本讲首先回顾其核心机制，并引入**全称量词（∀）**。

### 存在量词的执行逻辑

存在量词的语义是"至少存在一条记录满足条件"。其执行过程是对目标表做遍历：

- 逐条扫描，一旦找到满足条件的第一条记录，**循环立即终止**
- 不需要遍历完整张表
- 典型场景：判断某个学生是否有选课记录

> 存在量词是"早停"式的——找到一条就停，效率相对较高。

### 全称量词的执行逻辑

全称量词要求**所有记录**都满足指定条件。与存在量词的关键区别：

| 量词 | 遍历方式 | 终止条件 |
|------|----------|----------|
| 存在量词（∃） | 逐条扫描 | 找到第一条满足条件的记录即停止 |
| 全称量词（∀） | 逐条扫描 | 必须遍历全部记录才能得出结论 |

全称量词在实际中可以通过**双重否定**转化为存在量词的形式（不存在不满足条件的记录），二者逻辑等价。

### 实例：查询选修了全部课程的学生

用 Alpha 语言表达关系代数中的"除"操作：

- **外循环**：遍历课程表，每次取一门课程
- **内循环**：检查当前学生是否选修了该课程
- 若对课程表中的每一门课，该学生都存在选课记录 → 符合条件
- 核心思想：用全称量词表达**集合包含关系**

## 逻辑蕴含（Logical Implication）

### 概念引入

查询"选修了张三所选全部课程的学生学号"时，传统的全称量词写法不够灵活——因为学生选的课程只是全部课程的**子集**。此时需要引入**逻辑蕴含**。

逻辑蕴含的真值表（A → B）：

| 前件 A | 后件 B | A → B |
|--------|--------|-------|
| T | T | **T** |
| T | F | **F** |
| F | T | **T** |
| F | F | **T** |

> 关键结论：A → B 只有在 A 为真且 B 为假时才为假。也就是说，**前件为假时，蕴含式自动为真**。

### 用逻辑蕴含表达"包含"关系

逐门课程判断的逻辑：

1. **张三选了该课，当前学生也选了** → 前后件均为真，蕴含式为真（符合条件）
2. **张三选了该课，当前学生没选** → 前件真、后件假，蕴含式为假（**唯一不符合**的情况）
3. **张三没选该课，当前学生选了** → 前件假，蕴含式为真（当前学生的选课可以比张三多）
4. **张三没选该课，当前学生也没选** → 前件假，蕴含式为真

> 逻辑蕴含是 Alpha 语言中**最复杂的表达方式**，也是每年考试必考内容（通常 2–3 题）。理解它的关键在于记住：只有"他有而你无"才失败，"他无"的情况不影响结果。

## 聚集函数（Aggregation Functions）

Alpha 语言提供了一组聚集函数，用于将多条数据按某种规则汇总计算：

| 函数 | 含义 | 说明 |
|------|------|------|
| COUNT | 元组个数计数 | 需注意重复值的处理 |
| TOTAL | 累加求和 | 即 SUM，Alpha 中用 TOTAL 关键字 |
| AVG | 平均值 | 要求字段为数值类型（字符串需先转换） |
| MAX | 最大值 | — |
| MIN | 最小值 | — |

### 关于 COUNT 的注意事项

- `COUNT(ST.sdpt)`：统计系别的个数（去重与否取决于实现）
- `COUNT(ST.sname)` vs `COUNT(ST.*)`：如果存在同名同姓的学生，前者不去重会造成结果等于表的总记录数；在实际 SQL 中需要用 `DISTINCT` 显式去重
- `AVG(ST.age)`：若 age 被定义为字符串类型，则不能直接求平均，需先做类型转换

## 数据更新操作

Alpha 语言中数据更新的基本流程为三步：

1. **HOLD**：将目标记录从磁盘读入内存工作空间
2. **修改**：在工作空间中对记录进行增/删/改
3. **写回**：将工作空间中的修改结果写回磁盘

### 三类基本操作

| 操作 | 命令 | 流程 |
|------|------|------|
| 修改 | HOLD → 改字段值 → 写回 | 先拉取，在内存中改，再写回 |
| 新增 | 构建新元组 → 写回目标表 | 也可用 HOLD 方式先建工作空间 |
| 删除 | HOLD → DELETE → 写回 | 拉取后在工作空间中删除 |

### 通过"删 + 建"实现修改

一种常见做法是先删除旧记录，再新建一条新记录后写回，用组合方式间接实现修改效果。

### 删除与参照完整性

删除学生记录时，若选课表中存在对该学生学号的参照，系统一般有两种策略：

- **级联删除**（CASCADE）：删除学生时同步删除其选课记录
- **禁止删除**（RESTRICT）：存在参照记录时拒绝删除

## 完整性约束回顾

在本章小结中，老师再次强调关系数据库的三类完整性：

| 类型 | 含义 | 实现方式 |
|------|------|----------|
| 实体完整性 | 每条记录可唯一区分 | 定义主键（PRIMARY KEY） |
| 参照完整性 | 表与表之间的记录关联约束 | 定义外键（FOREIGN KEY） |
| 用户自定义完整性 | 具体业务规则约束 | 用户根据需求定义 |

> 做系统设计时，必须定义主键和外键。前两种完整性是强制性的。

## SQL 语言概述

### 为什么需要 SQL

关系代数和 Alpha 语言是理论基础，但实际应用中不会直接使用它们来操作数据库。**SQL（Structured Query Language）** 是工业标准，所有关系型 DBMS 都支持，使用简洁且易于理解。

### SQL 的三大语言类别

SQL 将 DBM 系统的三类语言**高度综合**，用统一的语法风格表达：

| 类别 | 全称 | 用途 | 典型关键词 |
|------|------|------|-----------|
| DDL | Data Definition Language | 定义/管理数据库对象（结构层面） | CREATE, DROP, ALTER |
| DML | Data Manipulation Language | 数据增删改查 | SELECT, INSERT, UPDATE, DELETE |
| DCL | Data Control Language | 安全与权限控制 | GRANT, REVOKE |

> DDL 的三条核心命令：**CREATE**（创建）、**DROP**（删除）、**ALTER**（修改）——与 DML 的 INSERT/DELETE 要严格区分。考试中常有同学混淆 CREATE TABLE 和 INSERT INTO，前者建空表结构，后者插入数据记录。

### SQL 的主要特点

1. **高度综合**：DDL、DML、DCL 统一于一套语法体系中
2. **高度非过程化**：用户只需说明"要什么"，不必关心数据物理存储和存取路径
3. **面向集合**：操作对象和结果都是记录的集合，与关系代数一脉相承
4. **可嵌入高级语言**：C/C++、Java、Python 等均可调用 SQL 语句——选课系统的"提交"按钮本质上就是一条 INSERT 语句

## DDL 详解：模式与表的创建/删除

DDL 管理的对象分为多个层次：

```
模式/数据库（Schema/Database）
  └── 表（Table）
        └── 视图（View）
              └── 索引（Index）
```

- **创建模式**：不同 DBMS 有不同叫法——SQL Server 称"创建数据库"，Oracle/MySQL 称"创建模式"
- **创建表**：定义列名、数据类型与值域
- **删除表**（DROP TABLE）：结构连同数据一并删除
- **修改表**（ALTER TABLE）：调整表结构

### SQL Server 中数据库的物理存储

创建一个数据库时，系统生成两个物理文件：

| 文件类型 | 扩展名 | 内容 |
|----------|--------|------|
| 数据主文件 | `.mdf` | 所有表数据 |
| 日志文件 | `.ldf` | 事务日志（记录数据库变更） |

可以配置文件的增长规则，防止数据膨胀耗尽磁盘空间导致系统崩溃。
