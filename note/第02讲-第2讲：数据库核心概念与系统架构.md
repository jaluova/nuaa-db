## 产品生态续：国产数据库的市场机遇

### 国产替代浪潮

- **人大金仓**（KingbaseES）：本书作者单位开发，国内市场份额近年快速上升
- 学校早期也有人做数据库系统，但十几年前缺乏产业环境支撑，纷纷放弃
- **华为 GaussDB**：定位为分布式文件管理系统，在 OS 文件系统之上构建，对外呈现为一套高并发、高性能的数据管理平台
- **阿里 OceanBase**：支撑 12306 等高并发场景

### 12306 的并发问题

早期 12306 和学校选课系统的"卡顿"本质不是"用户太多"，而是**并发数量过大**——同一时刻大量用户争抢同一资源。

解决思路：
1. **提升硬件**（有天花板，成本高）
2. **技术手段**：排队机制（请求入队，逐一处理）、并发控制（本书专设一章）

> 文件系统不支持真正的并发——操作系统对同一文件的访问是独占式的。

## 核心概念：DB / DBMS / DBS 三层结构

### 从底层到上层

```
数据库 (DB)  →  数据库管理系统 (DBMS)  →  数据库系统 (DBS)
```

- **数据库 (DB)**：大量数据有组织的集合，长期存储在计算机中，结构化、可共享
- **数据库管理系统 (DBMS)**：管理数据库的基础软件（如 MySQL、Oracle、SQL Server），位于 OS 之上
- **数据库系统 (DBS)**：在 DBMS 之上构建的应用系统（如选课系统、学生管理系统）

> MySQL 是 **DBMS**，不是"数据库"。选课系统是 **DBS**。

## 数据 vs 信息：严格区分

| 概念 | 定义 | 示例 |
|------|------|------|
| **数据** | 描述事物的符号记录 | "93"、"ABC" |
| **信息** | 数据 + 语义环境（上下文） | "某学生数据库成绩为 93" |

> **数据 + 环境 = 信息**。脱离环境，数据无意义。

在一般写作中两者常混用，但学术定义上存在本质区别。

## 数据的存储：逻辑 vs 物理

### 两次映射

```
用户界面（二维表格）
    ↕ 第一层映射：逻辑表示
内存中的数据结构
    ↕ 第二层映射：物理存储
磁盘上的二进制串
```

- **逻辑结构**：二维表、行列结构
- **物理存储**：磁盘上的二进制位，存在**行优先**和**列优先**两种组织方式
- 数据模型要解决的核心问题：逻辑表示与物理存储之间的映射转换

## 数据库的基本特征

### 1. 数据结构化
数据按一定结构（数据模型）组织，不是杂乱堆放

### 2. 可共享
多个用户/程序可同时访问

### 3. 冗余度尽可能小（但不可消灭）

**关键洞察**：冗余并非全是坏事。
- 学生表的学号与成绩表的学号是**冗余**的
- 但这种冗余恰恰是**维持表与表之间关联的纽带**
- 目标：冗余尽可能小，但绝不能完全消除——数据之间的**联系靠冗余来构建**

### 4. 数据独立性高

用参数输入为例说明：
- 按位置传参 `(1, 2, 3)` → 顺序改变则语义改变，程序需修改
- 按名称传参 `a=1, c=2, b=3` → 顺序无关，程序不变

**数据独立性**的含义：数据结构发生变化时，应用程序可以**保持不变**。

## 系统架构：C/S vs B/S

### C/S（Client/Server，客户端/服务器）

- 客户端需安装专用软件
- 优点：响应速度快，安全性好（局域网内），界面可丰富
- 缺点：**版本更新需逐台部署，维护代价高**

### B/S（Browser/Server，浏览器/服务器）

- 客户端只需浏览器，无需安装软件
- 所有程序部署在服务器端
- 优点：**升级方便**（只更新服务器），维护代价小
- 缺点：公网运行安全性要求更高

> 选课系统是典型的 B/S 架构。你们从未"更新"过教务系统客户端——因为它根本没有客户端，一切都在服务器端。

### B/S 的三层结构

```
浏览器 (Browser)
    ↓
Web Server (IIS/Apache/Nginx)
    ↓
DBMS (MySQL/Oracle/...)
    ↓
操作系统 → 文件系统 / 磁盘
```

### 多层架构的意义

当并发增大时，单台服务器成为瓶颈。解决方案：
1. **排队机制**：请求入队，逐一处理，保证每个请求都被正确响应
2. **水平扩展**：增加应用服务器数量，不同区域分流
3. **多层 C/S 架构**：大型系统（如 12306）必然是**多层架构**

## DBMS 的核心功能模块

一个完整的数据库管理系统应包含：

1. **数据定义**（Data Definition）：定义数据结构
2. **数据操纵**（Data Manipulation）：增删改查
3. **数据控制**（Data Control）：安全、并发、完整性

> MySQL、SQL Server、Oracle 等功能有差异，但核心体现在**管理能力**和**性能**的区别。
