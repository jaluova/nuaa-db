## 第三章复习：SQL语言（约20分）

### 三类SQL语言

[00:34] SQL语句分为三大类，这是基本功问题：

| 语言类型 | 分类 | 必会命令 |
|----------|------|----------|
| **DDL**（数据定义语言） | 定义 | CREATE TABLE / CREATE INDEX / CREATE VIEW |
| **DML**（数据操纵语言） | 操纵 | SELECT / INSERT / UPDATE / DELETE |
| **DCL**（数据控制语言） | 控制 | GRANT / REVOKE |

[01:06] 教师特别指出：创建索引、创建视图属于DDL——很多学生将"创建"当成DML（将INSERT理解为"创建数据"），这是基本概念的错误。DDL定义的是结构，DML操作的是数据。

> [02:11] 创建表、创建索引、创建视图——这些最基本的规定，一定是要会的。

### 查询的三大技术

[03:16] SQL查询的核心方法：

1. **连接查询**：多表做JOIN连接成一张大表，再做选择和投影——与关系代数一脉相承
2. **嵌套查询**（IN子查询）：子查询返回结果集，外层用IN判断
3. **分组统计**（GROUP BY + HAVING）：**关键区分**——WHERE对分组前记录筛选，HAVING对分组后结果筛选

> [05:58] 光在WHERE里面是不行的，WHERE是对没分组之前的所有记录去筛选，HAVING是对分组以后的那些记录里面来进行筛选。

**典型考题**："查询与张三选课门数一样的学生姓名"：

1. 先查出张三的选课门数
2. 对每个学生按学号分组计数（GROUP BY + COUNT）
3. HAVING COUNT(\*) = 张三的选课门数（此处必须用HAVING而非WHERE）
4. 再与学生表连接得到姓名

### 查询补充知识点

[06:56] 聚集函数（COUNT、SUM、AVG、MAX、MIN）是基础中的基础，必须会使用。

[07:26] **日期函数**：若查询条件涉及日期（如"查1999年出生的学生"），需要使用内嵌的日期函数（如YEAR(出生日期)）来提取年份进行匹配。

[08:10] **派生表查询**（教材第107页）：FROM子句中使用子查询结果作为临时表——教师建议要关注。

[08:24] **递归查询**（WITH RECURSIVE语法）：教师单独提到这是一个可能的区分度题型。

[08:42] **NULL值的处理**（教材第111页）：空值的处理规则在实际系统中频繁涉及。

> [09:46] 题目说查询有课程成绩的学生的信息，这里加一个条件——成绩IS NOT NULL。把这些没有课程成绩的人要撇掉。

[10:25] 选课操作向选课表插入记录，但学生可能没有考试就没有成绩——统计时必须排除这些NULL值。IS NULL和IS NOT NULL的用法不能遗漏。

### 视图创建

[11:09] 创建视图的基本语法：

```sql

```

> [11:07] 有些同学跟什么东西很多——乱七八糟的都有的，写什么INSERT的，有的写什么ALTER的。

> [12:07] 关键词和主要结构一个都错了，一分都没有。反过来讲，如果关键词和主要结构是对的，中间有小毛病，一般来讲就是给你个50%以上的分数。

## 第四章复习：数据库安全性（考得较少）

[13:26] 第四章相对考得较少，但基本命令要掌握。

**两种存取控制方式**：
- **DAC**（自主存取控制）：用户自主授权
- **MAC**（强制存取控制）：基于安全标签的强制规则

**核心命令**：

```sql
-- 授权与回收（DCL）
GRANT 权限 ON 对象 TO 用户/角色;
REVOKE 权限 ON 对象 FROM 用户/角色;

-- 用户与角色管理
CREATE USER ...;
CREATE ROLE ...;
```

> [14:40] 我记得有一年就考了一个——把什么样的权限授给哪个用户。你记不得就写不出来的。

GRANT（授权）和REVOKE（回收）两条命令，以及CREATE USER、CREATE ROLE两条命令，总共四条核心命令需会写。

## 第六章复习：关系数据理论（20分以上）—— 全书核心

### 完整的链式解题流程

[18:49] 第六章是全书最核心的章节，分值重且难度大。教师梳理了标准解题链路：

$$$$\\text{属性闭包 } X^+ \\xrightarrow{X^+ = U} \\text{候选码} \\rightarrow \\text{极小函数依赖集 } F_{min} \\rightarrow \\text{范式判定} \\rightarrow \\text{模式分解}$$$$

### 第一步：属性闭包计算

[21:37] **这是所有后续步骤的根基。**

> [21:48] 这个是所有人都会的——这是个死的套路。这个不会算，后面全是白搭。

### 第二步：候选码求法（属性分类法）

[22:05] 基于属性在函数依赖中出现的"位置"来分类：

| 属性出现位置 | 在候选码中？ | 策略 |
|-------------|------------|------|
| 只在左部出现 | **必在**候选码中 | 纳入基本集 |
| 只在右部出现 | **不在**候选码中 | 排除 |
| 左右都出现 | **可能**在 | 需逐一尝试加入 |
| 左右都不出现 | **必在**候选码中 | 必加入基本集 |

若 $$X^+ = U$$，则X为超码。通过组合尝试确定最小候选码。

### 第三步：范式判定

| 范式 | 判定条件 |
|------|----------|
| 1NF | 所有属性都是不可再分的原子值（所有关系自然满足） |
| 2NF | 无非主属性对码的**部分函数依赖** |
| 3NF | 无非主属性对码的**传递函数依赖** + 满足2NF |
| BCNF | 所有决定因素都包含码 |

[19:32] 教师举例：已知R中函数依赖 $$T \\to A$$，候选码为 $$MT$$。由于 $$MT \\to T \\to A$$，存在A对码MT的部分依赖（A可由MT的真子集T决定），因此R只属于1NF，不属于2NF。

[23:04] 往年曾考过证明题："任何二元关系至少属于第几范式"——答案是至少属于3NF以上。课堂中曾详细证明。

### 第四步：模式分解

[24:05] 证明过程不需要掌握，只需要会基本的分解操作：
- 3NF分解：将传递依赖链一拆为二
- 简单的分解操作即可，不要求掌握复杂证明

> [24:13] 不要求大家看证明。如果有传递它肯定不满足第三范式，把它一分为二就行了。

## 第九章复习：物理存储与B+树（约15分）

[28:50] 第九章是新增章节（第六版增加），但每年必考。

### 定长记录与变长记录

[29:06] 数据存储的基本组织方式。定长记录和变长记录在数据块中的组织格式需了解。

### B+树索引动态构建（核心考点）

[29:35] B+树索引是第九章最重要的考点。

**构建规则**：根据数据输入的**顺序**，动态构建B+树。

**节点分裂时的关键操作**：

> [31:37] 一种方式有些同学可能这边就12了，但实际上不满足B+树的均匀分布的特点。一般来讲它分裂出来以后，如果只有一个的话，往往会把8往这边挪过来——书上就是这样挪的。

[31:53] 例如节点有[2,3,4,8]，插入12后节点满需分裂。不是简单地让12独占新节点——而是将8移到新节点，使两边各有2个元素，上层节点存储分隔键值8和12。上层节点存储的是分隔键值而非数据本身。

[32:57] 当分裂后键值重新分配时，上层节点存储的分隔键值会相应调整（如从12变为8）。

### 查询代价估算

[33:28] B+树索引下的查询代价估算：

**主键索引查询**（如WHERE sno = '1001'，学号上有B+树索引）：

$$$$\\text{代价} = \\text{B+树层数（根到叶的块数）} + 1 \\text{次数据块读取}$$$$

> [34:20] 数据块本身至少是要读一次的，千万别漏了。

**非主键索引查询**（如WHERE name = '张三'，姓名上有索引）：
- 需额外考虑同名人数 — 同名人数决定叶节点数据块的读取数量
- 若同名不超过10人，可能在一个数据块内即可读取完毕

[34:50] 需要根据查询条件判断系统会选择全表扫描还是索引查找——权衡的关键在于同名人数与数据分布。

[35:50] 教师给出具体参数：学生表1万人，一个数据块存100条记录，同名不超过10人——这种情况下索引是有效的，同名记录在一个数据块内即可读完。

## 第十章复习：查询优化（约15分）

### 代数优化

[37:23] 两种优化思路：代数优化与物理优化。

**代数优化的步骤**：
1. 将查询画成语法树
2. 利用等价变换规则（如选择下推、投影下推）调整操作次序
3. 最终得到优化后的关系代数表达

### 物理优化

[38:07] 三种连接算法及其代价估算（教材第308页）：

| 连接算法 | 代价构成 |
|----------|----------|
| **嵌套循环连接** | 教材308页有块读写数的完整公式 |
| **排序归并连接** | 外表+内表各读一次 + 若未排序另加排序代价（有计算公式） |
| **哈希连接** | 了解基本思路 |

[38:34] 嵌套循环连接的代价估算往年考过——给定基本条件，计算需要读写的数据块数。

[39:09] 排序归并连接代价 = 外表块数 + 内表块数 + 排序代价（若两端未排序）。排序代价在教材中有专门计算公式。
