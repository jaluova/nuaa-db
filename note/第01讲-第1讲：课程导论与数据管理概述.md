## 课程目标：能做怎样的系统？

以选课系统为例，一个完整的信息系统至少需要以下层次：

1. **界面交互**
   - 图形化界面（如 Web 选课页面）
   - 命令行界面（如 C 语言的 `printf`/`scanf`）
2. **数据 I/O**：输入（键盘→系统）与输出（查询结果→屏幕）
3. **数据存储**：选课数据最终保存在服务器端，需要持久化
4. **数据管理**：不同类型的数据（学生信息、课程信息、成绩等）需要统一的管理方式

核心问题链：
> 数据类型多样 → 用什么**结构**统一表示？ → 表示之后如何**存储**？ → 存储结构如何影响**性能**？

## 数据管理技术的发展阶段

### 手工管理 → 文件管理 → 数据库管理

| 阶段 | 方式 | 缺陷 |
|------|------|------|
| 手工管理 | 纸质记录 | 效率极低 |
| 文件管理 | Word、Excel 等 | 海量数据管理能力不足，性能受限 |
| 数据库管理 | MySQL、SQL Server、Oracle 等 DBMS | — |

数据库管理系统（DBMS）相比文件系统的核心优势：**管理效率高、数据共享度高、冗余度低**。

## 大数据的概念（4V 特征）

大数据不能仅以"数据量大"来定义。一位专家的定义是：
> "当数据的复杂度超出人类处理能力时，即为大数据。"

这是一个**相对概念**，公认的四个评判维度：

1. **Volume（体量）**：数据量级超出传统处理能力
2. **Variety（多样性）**：除结构化数据外，还包括文本、图像、音频、视频等非结构化与半结构化数据
3. **Value（价值密度）**：海量数据中蕴含规律性信息，需要挖掘才能产生价值
4. **Velocity（速度）**：要求在线实时处理能力

> 老师提到"4V"但未明确是 Value 还是 Veracity，课堂上下文强调价值挖掘，此处暂记为 Value。

## 数据全生命周期的安全

数据生命周期：**产生 → 收集 → 存储 → 传输 → 使用**

各环节的安全措施：

| 环节 | 安全手段 | 涉及课程 |
|------|----------|----------|
| 存储安全 | 加密（存储加密，使用时解密，有性能代价） | 本书重点 |
| 传输安全 | 加密传输、量子通信（十五五重点产业方向之一） | 计算机网络 |
| 使用安全 | **身份鉴别**（用户名/密码）、**权限控制**（不同用户不同功能）、**密级控制**（秘密/机密/绝密） | 本书重点 |

使用安全的三层模型：
1. 用户鉴别（登录认证）
2. 权限授权（不同角色看到不同功能）
3. 密级访问控制（文档密级与人员密级匹配）

## 数据库管理系统产品生态

### 按数据模型分类

- **关系型数据库**（本书重点）：核心数据结构是**二维表格**，代表产品 MySQL、SQL Server、Oracle、PostgreSQL
- **文档型数据库**：面向大文本/文档管理，代表产品 MongoDB
- **时序数据库**：面向实时监控等时空数据场景（传统二维表不适合高频时间序列的存储与查询）

### 主流产品

| 类型 | 产品 | 特点 |
|------|------|------|
| 开源 | MySQL、PostgreSQL | 免费，中小型企业广泛使用 |
| 商业 | Oracle（甲骨文）、DB2（IBM）、SQL Server | 大型企业/银行/电力系统传统选择 |
| 国产 | 达梦 DM（第一家 A 股上市国产数据库公司）、OceanBase（蚂蚁集团，金融行业应用多）、GaussDB（华为） | 近年快速崛起 |

### 华为 GaussDB 的启示

华为早期全套引入 IBM + Oracle 系统，后来受制裁被迫自主替代，自研了 GaussDB 和上层 ERP 系统，实现**无缝切换**。这说明：

- 以前不可能做的底层数据库系统，现在**国产替代浪潮下出现了大量机会**
- 信息安全专业毕业生不仅可以在应用层做系统（如选课系统），**现在有机会去华为、中兴、达梦等公司做数据库底层核心软件**
