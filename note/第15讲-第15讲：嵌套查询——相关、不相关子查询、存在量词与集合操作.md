## 子查询的分类：不相关 vs 相关

### 不相关子查询（Uncorrelated Subquery）

**定义**：子查询的查询条件**不依赖**于外层查询。子查询可以**先独立执行**，得到一个结果集，再代入外查询。

**示例**：查询与"刘晨"在同一个系的学生。

```sql
SELECT sno, sname, sdept
FROM student
WHERE sdept IN (
    SELECT sdept FROM student WHERE sname = '刘晨'
);
```

执行流程：
1. 先执行子查询：`SELECT sdept FROM student WHERE sname = '刘晨'`，得到所在系。
2. 将结果代入外查询的 IN 条件。

> 不相关子查询的结果集是**确定的常量集合**，不随外循环而变化。这是判断是否"不相关"的根本标准——子查询的条件中是否出现了外查询的字段变量。

### 相关子查询（Correlated Subquery）

**定义**：子查询的查询条件**依赖于**外层查询。外层查询每处理一条记录，都需要向子查询**传递一个参数值**，子查询才能执行。

**示例**：找出每个学生超过其自身选修课程平均成绩的课程编号。

```sql
SELECT sno, cno
FROM sc x
WHERE grade >= (
    SELECT AVG(grade)
    FROM sc y
    WHERE y.sno = x.sno
);
```

执行流程（逐条驱动）：
1. 外循环从 `sc x` 取出第一条记录（如 1001 号学生、1 号课程、80 分）。
2. 将 `x.sno = '1001'` 传入子查询。
3. 子查询计算 1001 号学生的平均成绩。
4. 判断 80 分是否 >= 该平均成绩，若是则输出此记录。
5. 外循环移到下一条记录，重复步骤 2~4。

> 相关子查询**不能**先独立执行——因为它的条件依赖于外循环传参，单独执行无法获得 `x.sno` 的值。

### IN 与等于号的选用

| 情况 | 使用 |
|------|------|
| 子查询结果必为**单个值**（如唯一键查询） | 可用 `=` |
| 子查询结果可能为**多个值** | 必须用 `IN` |

> 实际应用中，即使当前数据唯一，也应优先使用 `IN` 以保证代码鲁棒性。例如"刘晨"可能在不同院系有同名者。

## ANY / ALL 量词

| 量词 | 含义 | 等价聚集函数替代 |
|------|------|----------------|
| `> ANY` | 大于子查询结果中的**任意一个** | `> MIN(...)` |
| `> ALL` | 大于子查询结果中的**每一个** | `> MAX(...)` |
| `< ANY` | 小于子查询结果中的**任意一个** | `< MAX(...)` |
| `< ALL` | 小于子查询结果中的**每一个** | `< MIN(...)` |

**ANY 示例**：查询比计算机系某个学生年龄小的其他系学生。

```sql
SELECT sno, sname, sage
FROM student
WHERE sage < ANY (
    SELECT sage FROM student WHERE sdept = 'CS'
)
AND sdept <> 'CS';
```

等价于 `sage < (SELECT MAX(sage) FROM student WHERE sdept = 'CS')`——比计算机系年龄最大的还小，即比其中至少一个要小。

**ALL 示例**：查询比计算机系所有学生年龄都小的其他系学生，用 `sage < ALL (...)`，等价于 `sage < (SELECT MIN(sage) ...)`。

> `ANY` 和 `ALL` 在实际项目中使用较少，大多数场景可用 `MAX`/`MIN` 等聚集函数替代，更直观易懂。

## EXISTS 与 NOT EXISTS

### 设计动机：效率

用 IN 或连接方式查"选修了 1 号课程的学生"，子查询需要遍历选课表**全部记录**。但如果运气好，某个学生选课记录在选课表第一条就找到了——后续遍历是**浪费**。

`EXISTS` 正为此而生：**只要找到一条匹配记录就立即返回 true，不再继续扫描**。

```sql
SELECT sname
FROM student
WHERE EXISTS (
    SELECT * FROM sc
    WHERE sc.sno = student.sno AND cno = '1'
);
```

与 IN 方式的本质区别：

| 方式 | 扫描策略 | 性能特点 |
|------|---------|---------|
| `IN` / 连接 | 对每个学生，完整扫描选课表 | 最坏情况：内表每轮全扫描 |
| `EXISTS` | 对每个学生，找到匹配即停止 | 最好情况：内表第一条即命中 |

> EXISTS 不关心子查询 SELECT 返回什么列——它只关心**是否存在**至少一条记录。因此子查询中通常写 `SELECT *`。

### 相关子查询

EXISTS 子查询的查询条件中引用了外层表的列（`sc.sno = student.sno`），因此它是**相关子查询**——外循环每次将学号传入，子查询才能执行。

### NOT EXISTS

`NOT EXISTS` 判断**不存在**匹配记录。例：查询没有选修 1 号课程的学生的姓名。

```sql
SELECT sname
FROM student
WHERE NOT EXISTS (
    SELECT * FROM sc
    WHERE sc.sno = student.sno AND cno = '1'
);
```

## 全称量词（∀）转换为存在量词（∃）

SQL **仅直接支持存在量词**（`EXISTS`），不支持全称量词（"对所有 x 都成立"）。必须通过逻辑等价转换：

> **∀x P(x)  ≡  ¬∃x ¬P(x)**

即："对所有 x 成立 P" 等价于 "不存在某个 x 使得 P 不成立"。

### 经典问题：选修了所有课程的学生

**关系代数**用除法（÷）解决：学生的选课集合是否包含全部课程编号。

**SQL 转换思路**：
- "学生选修了所有课程" = "不存在某一门课程该学生没有选"
- = `NOT EXISTS` (某门课程 `NOT EXISTS` (该学生选了这门课))

```sql
SELECT sname
FROM student
WHERE NOT EXISTS (
    SELECT * FROM course
    WHERE NOT EXISTS (
        SELECT * FROM sc
        WHERE sc.sno = student.sno
          AND sc.cno = course.cno
    )
);
```

嵌套结构分析：

| 层级 | 含义 | 类型 |
|------|------|------|
| 最内层 `sc.sno = student.sno AND sc.cno = course.cno` | 判断该学生是否选了当前课程 | 相关子查询（依赖两个外参数） |
| 中间层 `NOT EXISTS (...)` | 该学生未选当前课程 | — |
| 最外层 `NOT EXISTS (SELECT * FROM course WHERE ...)` | 不存在某门课该学生没选 | 相关子查询 |

> 这是 SQL 中理解难度最高的查询模式。核心在于三层嵌套的**双重否定**逻辑：外层 NOT EXISTS 对课程表遍历 + 内层 NOT EXISTS 判断选课不存在 = 所有课程都选了。

## 逻辑蕴含的 SQL 实现

**问题**：查询至少选修了"张三"所选全部课程的学生学号和姓名。

关系代数中的逻辑蕴含 `P → Q`：如果张三选了某门课，则该学生也选了这门课。

**等价转换**：`P → Q  ≡  ¬P ∨ Q  ≡  ¬(P ∧ ¬Q)`

即："不存在这样一门课程——张三选了（P 为真）而该学生没选（Q 为假）"。

```sql
SELECT DISTINCT sno
FROM sc x
WHERE NOT EXISTS (
    SELECT * FROM sc y
    WHERE y.sno = '张三的学号'
      AND NOT EXISTS (
          SELECT * FROM sc z
          WHERE z.sno = x.sno
            AND z.cno = y.cno
      )
);
```

> 逻辑蕴含只有一种情况为假：前件真而后件假。因此判断逻辑蕴含成立，等价于判断不存在"前件真且后件假"的情况。

## 集合操作（UNION / INTERSECT / EXCEPT）

SQL 支持对两个查询结果集执行集合运算：

| 操作 | 关键词 | 含义 |
|------|--------|------|
| 并 | `UNION` | 合并两个结果集，默认去重；`UNION ALL` 保留重复 |
| 交 | `INTERSECT` | 取两个结果集的公共部分 |
| 差 | `EXCEPT`（或 `MINUS`） | 从第一个结果集中去掉第二个结果集中的记录 |

> 集合操作要求两个查询的**列数相同、对应列类型兼容**。

### 交集 vs AND 的陷阱（高频考点）

**提出问题**：查询选修了 1 号课程**和** 2 号课程的学生的学号。

**错误写法**：
```sql
SELECT sno FROM sc WHERE cno = '1' AND cno = '2';
```
一行记录的 `cno` 不可能同时等于 1 又等于 2，此条件永远为假，返回空集。

**正确写法**（交集）：
```sql
SELECT sno FROM sc WHERE cno = '1'
INTERSECT
SELECT sno FROM sc WHERE cno = '2';
```

**等价写法**（嵌套）：
```sql
SELECT sno FROM sc WHERE cno = '1'
AND sno IN (SELECT sno FROM sc WHERE cno = '2');
```

> `AND` 是对**同行**的多个列条件做逻辑与；而"选修了 A 课且也选了 B 课"是对**同一个人、不同行**的判定。这必须用交集或嵌套子查询，不能用单行的 AND 来表达。

## 查询实现方式选择总结

同样一个查询需求，通常有多种 SQL 写法：

| 方式 | 适用场景 | 效率 |
|------|---------|------|
| 多表连接 + WHERE | 通用，大多数情况都能解决 | 取决于索引和连接策略 |
| 嵌套子查询（IN） | 集合成员判断 | 相关子查询效率可能较低 |
| EXISTS / NOT EXISTS | 存在性判断 | 相关子查询中通常效率更高 |
| 集合操作（INTERSECT/EXCEPT） | 集合的交、差运算 | 取决于 DBMS 优化器 |

> 考试无硬性规定时，多表连接是最"笨"但最稳妥的方式——几乎所有查询都可通过连接实现。但实际开发中应选择效率最优的方案。
