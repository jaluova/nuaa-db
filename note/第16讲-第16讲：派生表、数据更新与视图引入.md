## 集合操作回顾

### 并（UNION）

查询计算机系的学生及年龄不大于 19 岁的学生——两个结果集求并集。逻辑上等价于 `WHERE sdept = 'CS' OR sage <= 19`。

`UNION` 默认去除重复记录；若需保留重复，使用 `UNION ALL`。

### 交（INTERSECT）与差（EXCEPT）

| 操作 | 示例 | 含义 |
|------|------|------|
| 交 | `A INTERSECT B` | 既是计算机系且年龄不大于 19 岁的学生 |
| 差 | `A EXCEPT B` | 计算机系学生中年龄大于 19 岁的 |

> 部分 DBMS 中 `EXCEPT` 写作 `MINUS`（如 Oracle）。不同数据库的 SQL 方言存在细微差异，书上使用标准 SQL 语法，实际使用时应查阅对应系统的文档。

### 年龄判断与日期函数

若学生表存储的是**出生日期**而非年龄，判断"年龄不大于 19 岁"需用日期函数动态计算：

```sql
-- 标准 SQL 风格（书上）
WHERE YEAR(CURRENT_DATE) - YEAR(birth) <= 19

-- MySQL 风格
WHERE YEAR(NOW()) - YEAR(birth) <= 19
```

> 两种写法等价，考试时按教材风格书写即可，用实际 DBMS 的函数风格也不算错。核心理解：原始表中没有直接的"年龄"列，但通过表达式可从已有数据推导出来。

## 派生表（Derived Table）

### 概念

某些复杂查询难以用单条简单 SQL 表达，需要"分步走"：先得到一个中间查询结果，再在中间结果上继续查询。这个**临时生成的中间结果**称为派生表——它在查询执行时动态产生，查询结束即消失，不占用持久存储。

### 语法

派生表放在 FROM 子句中，用括号包裹子查询并指定别名：

```sql
SELECT sno, cno
FROM sc, (
    SELECT sno, AVG(grade) AS avg_grade
    FROM sc
    GROUP BY sno
) AS tmp
WHERE sc.sno = tmp.sno AND sc.grade > tmp.avg_grade;
```

执行流程：
1. 子查询生成临时表 `tmp`，包含每个学生的学号和平均成绩。
2. 将 `sc` 表与 `tmp` 做等值连接。
3. 过滤出成绩超过自己平均成绩的课程记录。

### 派生表 vs 视图

| 特性 | 派生表 | 视图 |
|------|--------|------|
| 存在形式 | 临时，查询结束即销毁 | 持久，存储在数据库字典中 |
| 物理存储 | 不存储数据 | 不存储数据（只存定义） |
| 复用性 | 仅限当前查询 | 可被多条查询复用 |
| 使用场景 | 一次性中间计算 | 频繁使用的逻辑表 |

> 实际开发中更常用的做法是：将频繁需要的中间查询**定义为一个视图**，之后将视图当作普通表来连接查询——代码更清晰，也便于维护。

## 数据更新：插入（INSERT）

### 单条记录插入

```sql
INSERT INTO 表名 [(列1, 列2, ...)]
VALUES (值1, 值2, ...);
```

两种写法：

| 写法 | 示例 | 要求 |
|------|------|------|
| 指定列名 | `INSERT INTO sc(sno, cno) VALUES('2001', '1')` | 未列出的列被设为默认值或 NULL |
| 不指定列名 | `INSERT INTO sc VALUES('2001', '1', NULL)` | **必须按表定义顺序给出所有列的值** |

> 不指定列名时，值的顺序和数量必须与建表时的列定义完全对应，否则出错。

### 选课操作的底层实现

学生提交选课时，系统循环执行：

```sql
INSERT INTO sc(sno, cno) VALUES('当前登录学号', '所选课程编号');
```

由于建表时成绩列可能未设默认值，DBMS 自动将成绩列赋为 **NULL**——这为教师后续录入成绩和查询"未出成绩"的记录提供了判断依据。

### 批量插入（子查询结果插入）

```sql
INSERT INTO 表名(列1, 列2)
SELECT 表达式1, 表达式2
FROM ...
WHERE ...;
```

将子查询产生的整个结果集**一次性**插入目标表，无需应用程序逐条循环。

## 数据更新：修改与删除

### 修改（UPDATE）

```sql
UPDATE 表名
SET 列1 = 值1, 列2 = 值2
WHERE 条件;
```

- 若省略 WHERE 条件，**全表所有行的该列都会被修改**，这是最常见的严重误操作之一。
- SET 可同时修改多列。

### 删除（DELETE）

```sql
DELETE FROM 表名
WHERE 条件;
```

- 同样，**省略 WHERE 将清空整张表**。
- 删除操作受参照完整性约束：若某记录被其他表的记录参照，且建表时定义了 `RESTRICT` 而非 `CASCADE`，则该删除将被 DBMS 拒绝。

> 增、删、改操作都可能破坏实体完整性和参照完整性。DBMS 会在执行前自动检查三类完整性约束，若违背则反馈错误并拒绝执行。这也是为什么我们在建表时就把约束定义好——由 DBMS 保证数据安全，远比在应用程序中写代码检查可靠。

## 实际应用案例

### 登录验证

登录界面的"确定"按钮实际上执行一条查询：

```sql
SELECT * FROM 用户表
WHERE 用户名 = '输入的用户名'
  AND 密码 = '输入的密码';
```

- 若返回一条记录：验证成功。
- 若返回空：登录失败。

而"注册"按钮则执行一条 INSERT 语句，将用户名和密码存入数据库。

### SQL 注入简介

当应用程序将用户输入与 SQL 语句**直接拼接成字符串**执行时，存在安全漏洞。

**示例**：用户在密码框中输入：

```
' OR '1'='1
```

拼接后的 SQL 变为：

```sql
SELECT * FROM user
WHERE username = 'admin' AND password = '' OR '1'='1';
```

`OR '1'='1'` 恒为真，绕过密码验证。更危险的情况下，攻击者可输入 `'; DROP TABLE user; --` 来删除整张表。

> 这不是本课程的重点要求，但它是数据库程序开发中必须防范的安全问题。解决办法包括参数化查询（PreparedStatement）、输入校验等，感兴趣的同学可以课后深入了解。

## 视图（View）初步

视图是一个**虚拟表**——它不存储实际数据，只保存查询定义。对视图的操作在执行时会被转化为对基本表的操作。

视图的主要作用：

1. **简化复杂查询**：将多表连接的常用查询定义为视图，后续直接 `SELECT * FROM 视图`。
2. **安全控制**：只授予用户对视图的访问权限，隐藏敏感列（如工资）。
3. **逻辑独立性**：基本表结构变化时，只需修改视图定义，应用程序无需改动。

> 上节课讲的派生表是"一次性"的临时表，而视图是"持久化"的查询定义。两者逻辑上类似，但视图可被反复使用。下一讲将详细讨论视图的创建与管理。

## DQL 全阶段总结

| 阶段 | 内容 | 复杂度 |
|------|------|--------|
| 单表查询 | SELECT + FROM + WHERE + ORDER BY | 基础 |
| 分组与聚集 | GROUP BY + HAVING + 聚集函数 | 中等 |
| 多表连接 | 等值连接、自身连接、外连接 | 中等 |
| 嵌套查询 | 不相关/相关子查询、IN/EXISTS | 较难 |
| 集合操作 | UNION / INTERSECT / EXCEPT | 中等 |
| 全称量词/除法/蕴含 | NOT EXISTS 双重否定转化 | 最难 |
| 派生表 | FROM 子句中的子查询 | 中等 |
| 数据更新 | INSERT / UPDATE / DELETE | 较易 |
