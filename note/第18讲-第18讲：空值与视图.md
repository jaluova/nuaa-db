## 空值处理进阶

### 空值回顾

- `NULL` 是数据库中特殊的常量，不是空字符串 `''`，也不是数字 `0`
- 取消成绩不是删除记录，而是将该学生的成绩字段赋为 `NULL` [01:08]
- 外连接中，当匹配不到对应记录时，会自动产生空值

### 空值判断

> [02:04] **重要**：判断是否为空只能用 `IS NULL` 或 `IS NOT NULL`，不能用等号 `= NULL`。

### 哪些属性可以取空值？

| 约束类型 | 能否取空值 |
|---------|-----------|
| **主码属性** | 不能（实体完整性要求非空且唯一） |
| **外码属性**（仅受参照完整性约束） | 理论上可以取空 |
| **同时是主码又是外码** | 不能取空（受多重约束） |

> [03:36] 选课表中的 `Sno` 既是联合主键的一部分（实体完整性要求非空），又是参照 Student 表的外码（参照完整性允许空），受到两重约束，最终实体完整性优先——**不能为空**。

### NULL 在运算中的行为

| 运算类型 | 规则 | 示例 |
|---------|------|------|
| **算术运算** | NULL 与任何值运算结果为 NULL | `60 + NULL` = NULL |
| **比较运算** | NULL 与任何值比较结果为 UNKNOWN | `Grade > 60` 当 Grade 为 NULL |
| **逻辑运算** | 遵循三值逻辑 | 见下表 |

### 三值逻辑真值表

| X | Y | X AND Y | X OR Y | NOT X |
|---|---|---------|--------|-------|
| T | U | U | T | F |
| F | U | F | U | T |
| U | U | U | U | U |

（T=真，F=假，U=不确定）

### 实际影响

**问题**：计算学生平均成绩时，若有学生成绩为 NULL，会导致什么？

```sql
-- 错误写法：NULL会导致整组平均值为NULL
SELECT AVG(Grade) FROM SC GROUP BY Sno;

-- 正确写法：过滤掉空值
SELECT AVG(Grade) FROM SC
WHERE Grade IS NOT NULL
GROUP BY Sno;
```

> [05:12] 如果不加 `WHERE Grade IS NOT NULL`，因为存在成绩为 NULL 的记录，平均成绩可能算不出来。

**查询不及格学生**时需注意：

```sql
-- 需要包含缺考（成绩为NULL）的学生
SELECT Sno FROM SC
WHERE Grade < 60 OR Grade IS NULL;
```

> [10:09] 不及格的学生应该包括缺考的——缺考就是没成绩（NULL），如果只写 `Grade < 60` 会漏掉这部分学生。

## 视图（View）

### 什么是视图？

> [11:38] 视图是一个**虚表（逻辑表）**，它只有逻辑结构，**不存储实际数据**。数据仍然存储在基本表中。

| 对比项 | 基本表 | 视图 |
|-------|--------|------|
| 数据存储 | 实际存储数据 | 不存储数据（仅有定义） |
| 物理存在 | 有对应的物理文件 | 只有数据字典中的定义 |
| 数据来源 | 直接存储 | 访问时从基本表动态导出 |

视图可以从一个或多个基本表（甚至其他视图）导出，支持多层嵌套定义。

### 视图创建语法

```sql
CREATE VIEW 视图名 [(列名1, 列名2, ...)]
AS
子查询
[WITH CHECK OPTION];
```

**关键限制**：子查询中**不能包含** `ORDER BY` 和 `DISTINCT` [16:39]。

**创建时机**：定义视图时，DBMS 只把视图定义存入数据字典，**不执行**其中的 SELECT 语句。实际查询在用户访问视图时才执行。

**示例**：创建信息系学生视图

```sql
CREATE VIEW IS_Student
AS
SELECT Sno, Sname, Sage
FROM Student
WHERE Sdept = 'IS';
```

列名默认为 SELECT 中的字段名，也可在视图名后显式指定（如 `IS_Student(a, b, c)`），实现列名隔离。

### 视图上的查询——查询转换机制

> [30:25] 视图本身没有数据，DBMS 会自动将对视图的查询转化为对基本表的查询。

**转化过程**：视图查询条件 + 视图定义中的 WHERE 条件 -> 合并为对基本表的完整查询

```sql
-- 用户对视图的查询
SELECT * FROM IS_Student WHERE Sage < 20;

-- DBMS 自动转化为
SELECT Sno, Sname, Sage
FROM Student
WHERE Sdept = 'IS' AND Sage < 20;
```

视图与基本表地位等同——可以在查询中与基本表做连接。

### WHERE vs HAVING 深度辨析

**关键示例**：查询平均成绩大于90分的学生

```sql
-- 错误写法：WHERE 中不能用聚集函数
SELECT Sno, AVG(Grade) FROM SC
WHERE AVG(Grade) > 90    -- ❌ 错误！
GROUP BY Sno;

-- 正确写法：聚集函数条件必须放在 HAVING 中
SELECT Sno, AVG(Grade) FROM SC
GROUP BY Sno
HAVING AVG(Grade) > 90;  -- ✅ 正确
```

| 对比维度 | WHERE | HAVING |
|---------|-------|--------|
| 作用对象 | 原始表中的每条记录 | 分组后的每个组 |
| 能否使用聚集函数 | 不能 | 能 |
| 执行顺序 | 分组前筛选 | 分组后筛选 |

> [34:40] 两个地方都可以给条件，但有本质区别。WHERE 是在所有原始记录上筛选，HAVING 是对分组后的每组数据做条件判断。放到不同地方，含义完全不同。

> [38:11] 周老师特别提醒：期末考试如果考这个，每年都有同学写错。写成 `WHERE AVG(grade) > 90` 看着很顺，但逻辑上严重错误。

### 视图的更新操作（受限）

视图支持增删改操作，但**受到限制**：

**允许更新的情况**：视图行列直接对应基本表的行列

```sql
-- 对 IS_Student 视图插入
INSERT INTO IS_Student VALUES ('2021005', '张三', 20);
-- 自动转化为对 Student 表的插入，Sdept 自动填 'IS'
```

**WITH CHECK OPTION 的作用** [20:52]：确保通过视图插入/修改的数据满足视图定义的 WHERE 条件。如对 IS_Student 视图插入时，DBMS 自动将 Sdept 赋值为 'IS'。

**不能更新的情况**：视图中包含聚集函数、表达式等派生数据时

> [41:34] 如果视图定义中属性用到了聚集函数（如 AVG），则该属性无法做更新操作——因为无法映射回基本表的原始记录。

**示例**：不能修改平均成绩视图中的平均成绩值

```sql
-- 视图定义
CREATE VIEW S_G(Sno, Gavg) AS SELECT Sno, AVG(Grade) FROM SC GROUP BY Sno;

-- 此更新无法执行——平均成绩是统计值，不是原始数据
UPDATE S_G SET Gavg = 90 WHERE Sno = '2021001';  -- ❌ 不可行
```

### 视图的五大作用

1. **简化用户操作**：将复杂多表查询封装为单表视图，前端只需简单查询
2. **多角度看待同一数据**：同一张学生表可为不同院系定义不同视图
3. **逻辑独立性**：统计规则改变时，只改视图定义，前端代码不变 [26:56]
4. **安全保护（隔离）**：各院系教务员只能看到本院学生，看不到其他院系
5. **更清晰表达查询**：将业务逻辑封装在视图定义中
