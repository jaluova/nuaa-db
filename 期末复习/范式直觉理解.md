# 关系范式 · 从术语到判定（完整版）

> 范式判定出错，通常不是因为"范式规则记错了"，而是因为**底层术语没搞清**。
> 本文从一张具体表出发，每个术语先定义再举例，最后才给伪代码。

---

## 阶段零：一张具体表

假设要记录：**哪个学生（S#）选了哪门课（C#），由哪位老师（T#）教，老师叫什么（Tname），考了多少分（Grade）**。

| S# | C# | T# | Tname | Grade |
|----|----|----|-------|-------|
| 01 | C1 | T1 | 张老师 | 85 |
| 02 | C1 | T1 | 张老师 | 90 |
| 03 | C1 | T1 | 张老师 | 78 |
| 01 | C2 | T2 | 李老师 | 92 |
| 02 | C2 | T2 | 李老师 | 88 |

**给定的函数依赖 F**（就是业务规则）：

$$
\begin{aligned}
\{S\#, C\#\} &\to Grade \quad &\text{—— 学号+课程号，确定成绩} \\
T\#           &\to Tname  \quad &\text{—— 教师号确定教师姓名} \\
C\#           &\to T\#    \quad &\text{—— 课程号确定授课教师（一门课只有一个老师教）}
\end{aligned}
$$

属性全集 $U = \{S\#, C\#, T\#, Tname, Grade\}$。

---

## 阶段一：术语清单（每个都带例子）

### 1. 函数依赖 $X \to Y$（Functional Dependency）

**定义**：任意两条元组（行），如果 $X$ 上的值相同，则 $Y$ 上的值**必须**相同。

**如何从数据中验证**：扫一遍表，找出 $X$ 值相同的行，看它们的 $Y$ 值——只要有一对反例，这个依赖就不成立。

**从上面表看例子**：

- $\{S\#, C\#\} \to Grade$ → 成立。没有任何一个学生同一门课有两个不同成绩。
- $C\# \to T\#$ → 成立。C1 对应的三行全是 T1，C2 对应的两行全是 T2。
- $S\# \to Grade$ → **不成立**。01 号学生有 85 也有 92，同一个 S# 对应不同 Grade。

> 函数依赖是**业务规则**，不是从数据"归纳"出来的。数据只是验证它当前是否被遵守。

---

### 2. 平凡依赖 vs 非平凡依赖

| 类型 | 定义 | 例子 |
|------|------|------|
| **平凡依赖** | $X \to Y$ 且 $Y \subseteq X$ | $\{S\#, C\#\} \to S\#$（右边是左边子集——废话） |
| **非平凡依赖** | $X \to Y$ 且 $Y \not\subseteq X$ | $\{S\#, C\#\} \to Grade$（Grade 不在左边，有信息量） |

> 我们讨论的全是**非平凡依赖**。平凡依赖永远成立，没讨论价值。

---

### 3. 属性闭包 $X_F^+$（Closure）

**定义**：给定属性集 $X$ 和函数依赖集 $F$，从 $X$ 出发能推导出的**全部属性**的集合。

**为什么重要**：$X_F^+$ 告诉你"知道 $X$，你实际上就知道了什么"。候选码、超键、范式判定全部以此为根基。

**算法（手工版）**：

1. 令 $result = X$
2. 扫描 $F$ 中每一条 $Y \to Z$，若 $Y \subseteq result$，则 $result = result \cup Z$
3. 重复步骤 2，直到 $result$ 不再变大
4. 返回 $result$

**例子**：在本文的 $F$ 下，求 $\{S\#\}_F^+$

| 轮次 | result | 触发的 FD | 原因 |
|------|--------|-----------|------|
| 初始 | {S#} | — | — |
| 第1轮 | {S#} | 无 | 每条 FD 的左边都不在 {S#} 内 |
| 结束 | **{S#}** | | result 没变大，停止 |

再求 $\{C\#\}_F^+$：

| 轮次 | result | 触发的 FD | 原因 |
|------|--------|-----------|------|
| 初始 | {C#} | — | — |
| 第1轮 | {C#, T#} | C# → T# | C# ⊆ {C#} |
| 第2轮 | {C#, T#, Tname} | T# → Tname | T# ⊆ {C#, T#} |
| 第3轮 | 不变 | — | 停止 |

$\{C\#\}_F^+ = \{C\#, T\#, Tname\}$。知道课程号，就能知道谁教、老师叫啥。

---

### 4. 超键（Superkey）

**定义**：属性集 $X$ 满足 $X_F^+ = U$（闭包 = 全部属性）。

**直觉**：知道 $X$ 的值，就能**唯一确定**表中一行。

**例子**：

- $\{S\#, C\#, Grade\}_F^+$ → 包含 {S#, C#}，触发所有 FD → 闭包 = U。**是超键，但太大了**（Grade 多余）。
- $\{S\#, C\#\}_F^+$ → 包含 {S#, C#}，触发 C#→T#→Tname，加上 Grade。**是超键**。

---

### 5. 候选码（Candidate Key）

**定义**：**最小的**超键——超键中去掉任意一个属性就不再是超键。

**通俗说法**："能唯一确定一行的最少属性组合"。

**例子**：

- $\{S\#, C\#\}$ 去掉 S# → {C#}⁺ = {C#, T#, Tname} ≠ U → 去掉不行
- $\{S\#, C\#\}$ 去掉 C# → {S#}⁺ = {S#} ≠ U → 去掉不行
- **{S#, C#} 是候选码**。唯一候选码。

---

### 6. 主属性 vs 非主属性（Prime / Non-Prime）

| 术语 | 定义 | 本文例子 |
|------|------|----------|
| **主属性** | 出现在**任意一个**候选码中的属性 | S#, C# |
| **非主属性** | 不在**任何一个**候选码中的属性 | T#, Tname, Grade |

> 如果有多个候选码（例如 AB, AC, AD），主属性 = A ∪ B ∪ C ∪ D 的并集。

---

### 7. 完全依赖 vs 部分依赖（Full vs Partial Dependency）

**完全依赖**：$X \to Y$，但去掉 $X$ 中**任意**一个属性后，依赖不再成立。

> 形式化：对于 $X$ 的所有真子集 $X'$，$X' \to Y$ 都不成立。

**部分依赖**：存在 $X$ 的某个**真子集** $X'$，也能推出 $Y$。

**例子**：

- $\{S\#, C\#\} \to Grade$ → **完全依赖**。去掉 S#，(C#)⁺ = {C#, T#, Tname}，不包含 Grade。去掉 C#，{S#}⁺ = {S#}，不包含 Grade。
- $\{S\#, C\#\} \to T\#$ → **部分依赖**。因为 C# 是 {S#, C#} 的真子集，而 C# → T# 本来就成立。S# 对确定 T# 没贡献，多余。

---

### 8. 传递依赖（Transitive Dependency）

**定义**：存在 $X \to Y$，$Y \to Z$（$Y \not\to X$，$Z \not\subseteq Y$），且 $X$ 是候选码，$Z$ 是非主属性。

**通俗版**：非主属性 $Z$ 不直接依赖候选码，而是**通过另一个非主属性 $Y$ 拐了个弯**。

**例子**：

- 候选码是 {S#, C#}
- C# → T# （T# 是非主属性，被候选码的真子集决定——这是部分依赖）
- T# → Tname （T# 是非主属性）
- 于是 C# → T# → Tname

只看 Tname：它最终被 C# 决定，但 C# 不是码，T# 也不是码。Tname 是通过非主属性 T# "拐弯"认识的——这就是**传递依赖**。

> 传递依赖的前提是先有部分依赖或非超键依赖。把表拆成 2NF 后，如果还有，就是经典的"非主 → 非主"传递。

---

## 阶段二：范式判定

**前置：先完成以下计算**（缺一不可）：

```
CandidateKeys = 所有候选码
PrimeAttrs    = 所有候选码中包含的属性的并集
NonPrimeAttrs = U - PrimeAttrs
```

本文结果：CandidateKeys = {{S#, C#}}，PrimeAttrs = {S#, C#}，NonPrimeAttrs = {T#, Tname, Grade}。

---

### 2NF

**定义**：不存在非主属性对候选码的**部分函数依赖**。

```
Function Is2NF:
    For each 非平凡 FD X -> A in F:        // A 是单个属性
        If A in NonPrimeAttrs:              // 右边是非主属性
            For each CK in CandidateKeys:
                If X ⊂ CK:                  // X 是 CK 的真子集（不是整个 CK）
                    Return False            // ✗ 部分依赖：非主属性只认半个键
    Return True
```

**本文判定**：C# → T#，T# 是非主属性，C# 是候选码 {S#, C#} 的**真子集** → **不满足 2NF ✗**。

---

### 3NF

**定义**：满足 2NF，且不存在非主属性对候选码的**传递函数依赖**。

等价表述：不存在非主属性被**非超键**决定。

```
Function Is3NF:
    For each 非平凡 FD X -> A in F:
        If A in NonPrimeAttrs:              // 右边是非主属性
            If X_F⁺ ≠ U:                    // X 不是超键
                Return False                // ✗ 非超键 → 非主属性
    Return True
```

> 注意：如果 A 是**主属性**，即使 X 不是超键，3NF 也放行。这是 3NF 和 BCNF 的唯一区别。

**本文判定**（假定已拆到 2NF，只看 CT(C#, T#, Tname)）：

- C# → T#：T# 是非主属性，C#_F⁺ = {C#, T#, Tname} = U → C# 是超键 ✓
- T# → Tname：Tname 是非主属性，T#_F⁺ = {T#, Tname} ≠ U → T# 不是超键 → **不满足 3NF ✗**

---

### BCNF

**定义**：每个非平凡函数依赖的**左边都是超键**。

```
Function IsBCNF:
    For each 非平凡 FD X -> Y in F:
        If X_F⁺ ≠ U:                        // X 不是超键
            Return False                    // ✗ 决定别人的必须是超键
    Return True
```

> 和 3NF 的区别：少了 `A in NonPrimeAttrs` 的豁免。右边不论是不是主属性，左边必须是超键。

**BCNF 例子**：R(S#, C#, T#)，候选码 = {(S#, C#), (S#, T#)}，F = {T# → C#}

- 主属性 = {S#, C#, T#}，没有非主属性
- 2NF：没有非主属性 → 自动满足 ✓
- 3NF：没有非主属性 → 自动满足 ✓
- BCNF：T# → C# 非平凡，T#⁺ = {T#, C#} ≠ U → T# 不是超键 → **不满足 BCNF ✗**

---

### 三级关系总结

```
BCNF ⊂ 3NF ⊂ 2NF ⊂ 1NF
（满足内圈自动满足外圈）
```

| 范式 | 检查什么 | 伪代码关键条件 |
|------|---------|---------------|
| 2NF | 非主属性是否部分依赖候选码 | `A ∈ NonPrime ∧ X ⊂ CK` |
| 3NF | 非主属性是否被非超键决定 | `A ∈ NonPrime ∧ X⁺ ≠ U` |
| BCNF | 是否有非超键在左边 | `X⁺ ≠ U`（不管右边是啥） |

**3NF 和 BCNF 的唯一差距**：存在 $(\text{非超键}) \to (\text{主属性})$ 时，3NF 说"OK 反正右边是主属性"，BCNF 说"不行，左边必须够格"。

> 推论：如果所有候选码都是**单属性**，则不可能存在"非超键 → 主属性"，此时 3NF ≡ BCNF。
